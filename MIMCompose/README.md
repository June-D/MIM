# MIMCompose

PC 桌面客户端（Compose Multiplatform）。

> 产品定位、安全内核边界与不可弱化的红线，见仓库根目录 README 的
> 《产品基调（共识）》。改这个客户端前先读那一节。

## 定位

当前先做透桌面端，再把同一套状态与职责划分复用到手机端。

- 已有：注册 / 登录 / 找回密码 → 联系人 → 聊天 → 设备；真实端到端收发、撤回、
  已读、离线队列、WebSocket 推送、未读数、清除会话、设备管理、安全码核对、
  添加联系人、好友备注、屏蔽、移除好友、记住账号密码、用户协议
- 不在这里：协议与密码学。基准实现在 `MIMCore`，实际执行在 `MIMCoreRust`
  （C ABI / JNI）。本模块只做传输、入库与 UI 语义

这样分层的目的：界面只表达业务语义，密码学独立演进，两端互不阻塞。

## 桌面布局与交互

宽窗口下是**两栏工作区**：左侧 312dp 会话列表固定可见，右侧是聊天详情，
点左边就换右边，不用在列表与对话之间来回切换；没有选中会话时右栏是空态。
窗口默认 1120×760，最小 880×620，打开时居中。

交互细节（都是本机行为，不涉及协议）：

- 所有可点区域有悬停底色、按下态和手型光标；图标按钮悬停 450ms 出现 tooltip，
  图标不再靠猜。
- 会话行悬停时右侧的时间/角标让位给「⋯」，置顶等操作不必记快捷键；
  长按整行同样能打开该菜单。
- 消息按「同一人 + 3 分钟内」分组：组内 3dp、组间 12dp，气泡只在一组的两端收圆，
  时间和已读状态退到组尾显示一次，不再每条重复。
- 往上翻历史时右下出现「回到最新」，点一下回到底部。
- `⌘/Ctrl + K` 直接进消息搜索；密码框有显隐开关。
- 搜索框统一为 40dp 紧凑样式（聚焦才提亮边框），登录表单仍用带 label 的大输入框。

## 运行

```bash
# 推荐：一条命令检查环境并启动（自动构建带 JNI 的 Rust 动态库）
MIMCompose/run-desktop.sh
MIMCompose/run-desktop.sh --check           # 只检查，不启动界面

# 等价的手动方式
cd MIMCompose
./gradlew :composeApp:run          # 演示后端（内存）
./gradlew :composeApp:desktopTest  # 状态流与联调测试

MIM_SERVER_URL=http://127.0.0.1:8080 \
MIM_NATIVE_LIB=../MIMCoreRust/target/release/libmim_core_rust.dylib \
  ./gradlew :composeApp:run
```

首次构建会下载 Gradle 与 Compose 依赖。国内网络可加 `MIM_GRADLE_MIRRORS=1`
启用 Maven 镜像。

当前测试 19 项：11 状态（演示后端）、1 本地加密往返、7 真实服务端联调
（需要 `MIM_SERVER_URL` 与 `MIM_NATIVE_LIB`；未设置时联调用例会跳过）。

### 当前接入范围

| 能力 | 演示后端 | 真实后端（SecureBackend） |
|---|---|---|
| 登录 | 模拟 | `POST /login/token`，令牌绑定设备 |
| 设备与密钥 | 无 | Rust 生成，登记 + 上传（缺失时自动补） |
| 联系人 | 固定两条 | `GET /chat/contacts`（分组展开） |
| 发送 | 内存回声 | 首条消息 / sealed 消息，Rust 组装后投递 |
| 接收 | 无 | 轮询 `/undelivered`，Rust 解密 + 落缓存 |
| 历史 | 内存 | 本地**加密缓存**（换设备或清库后不保留） |
| 撤回 | 无 | 发送时生成凭证；`POST /message/recall`，本地立即置「已撤回」 |
| 已读回执 | 无 | 打开会话 `POST /message/read`；自己消息的已读靠历史轮询 |
| 离线队列 | 无 | 投递失败入队，只重发同一份密文，不重复推进棘轮 |
| 实时推送 | 无 | WebSocket `/websocket/*`，收到 100010/100012/100014 即触发同步 |
| 设备管理 | 无 | `GET /device` 列表 + `DELETE /device/{id}` 注销 |
| 二次验证 | 无 | `POST /user/2fa/setup|enable|disable|recovery-codes`，开启后强制其它设备重新登录 |
| 安全码 | 无 | 60 位安全码（与 Java 同算法），按对端设备逐个展示 |
| 未读数 | 内存计数 | `GET /message/unread/{peer}`，联系人页角标以服务端为准 |
| 清除会话 | 无 | `POST /message/clear`，可只清自己的或双方清除；本地缓存一并丢弃 |
| 图片 / 语音 / 文件 | 无 | 内容用一次性密钥 AES-GCM 加密后上传 `/media`；消息里只带引用、密钥与文件名 |
| 消息搜索 | 无 | 只在本地加密缓存里检索；命中后进会话并滚到该条 |
| 会话置顶 | 无 | 本机偏好（`pinned.bin`），置顶优先排序，不上报服务端 |
| 未读定位 | 无 | 打开有未读的会话时滚到第一条未读并画分界 |
| 安全码变更提醒 | 无 | 记录见过的安全码；再次不一致时警示，需人工重新核对 |
| 添加联系人 | 无 | `GET /chat/search` 搜索 → `POST /chat/requests` 申请 → 对方同意 |

协议计算全部在 Rust 核心；Kotlin 只做传输、入库与 UI 语义。

### 实时推送与兜底

`SecureBackend.listenPush` 连 `ws(s)://host/websocket/compose`，握手带
`Authorization` 与 `X-Device-Id`；只把「有新数据」通知给上层，具体拉取仍走 HTTP。
收到新消息 / 已读回执 / 撤回事件即时触发一次同步；
收到对方「清除会话」通知（100019）时直接丢弃本地缓存，避免显示已被抹掉的消息。

同时保留 3 秒轮询兜底：推送断开或丢失时最多延迟 3 秒；重连间隔 3 秒，
25 秒无帧就发文本心跳。

### 状态刷新

`historyStates` 每轮对**当前打开的会话**查一次历史，更新已读与撤回状态；
其它会话在下次打开时刷新（推送只会触发同步，不会直接改本地状态）。

### 添加联系人

联系人页「添加」进入添加页：输入用户名搜索 → 发送申请；对方的申请在
「待我处理」里同意或拒绝。申请必须对方同意才建立关系，不存在静默加好友。
收到申请 / 同意 / 拒绝的推送（100016~100018）会即时刷新申请列表；
对方同意后联系人列表立刻出现对方，不需要重新登录。

### 二次验证

联系人页「更多」→「安全设置」：

- 未开启：生成共享密钥与 `otpauth://` 链接（可复制），输入验证器当前 6 位码启用；
  服务端会作废其它设备并给本机换发令牌，客户端立即换用新令牌。
- 已开启：可用「当前密码 + 6 位验证码或一条恢复码」重新生成恢复码或关闭；
  恢复码只在生成时展示一次，服务端只存哈希。
- 登录页在账号已开启时要求额外输入验证码或恢复码（服务端 40102）。

### 连接与传输安全

地址由 `MIM_SERVER_URL` 指定，HTTP 与 WebSocket 同源推导（https → wss）：

- 只接受 `https://`；`http://` 仅放行本机回环（`127.0.0.1` / `localhost` / `::1`），
  其余明文地址直接拒绝并停在说明页——不静默降级成演示后端，避免「以为连上了」。
- 内网调试确实需要明文时设 `MIM_ALLOW_INSECURE=1`，并自行确认链路可信。
- 自签 CA：把证书导入 JVM truststore
  （`JAVA_TOOL_OPTIONS="-Djavax.net.ssl.trustStore=... -Djavax.net.ssl.trustStorePassword=..."`）。
- 大写协议名会被规范成小写、尾部斜杠会去掉；解析失败给出可读原因而不是堆栈。

理由：端到端加密只保护内容，口令、JWT 与「谁和谁在通信」都在 HTTP 头上。

### 外观与主题

- 默认跟随系统外观；「更多」→「外观：跟随系统」点一下在
  跟随系统 / 浅色 / 深色 之间循环（当前只存内存，重启回到跟随系统）。
- 颜色只在 `ui/Theme.kt` 定义。深色不是把浅色调暗：强调色（`Teal`）与实心块
  （`TealFill`）拆成两个 token —— 深色下前者要提亮才能当字色，后者要保持足够深
  以承载白字；另有 `OnTeal`、`TealDeep`、`OnBrassSoft` 专管各自容器上的文字。
- 分层方式随主题切换：浅色下对方气泡用极淡投影浮起，深色投影看不见，改用 1px 边框
  （两者只取其一，避免「1px 边 + 宽投影」的幽灵卡片）。
- 调色板是进程级单例（不是 Compose 状态），所以切换主题用 `key(darkTheme)` 重建界面
  子树，保证所有读色的地方都拿到新值；后端与账号状态在外层，不受影响。
- 空态收进 `ui/EmptyState.kt`：圆底 54dp、图标 22dp、说明限宽 236dp 居中、
  可选主操作，左右两栏共用同一规格。

### 本机登录保护

同一台设备连续 3 次输入错误的登录密码时，客户端立刻删除该账号在这台设备上的
全部本地加密数据（`~/.mim/<用户名>/` 整个目录：设备标识、密钥包、会话状态、
消息缓存、离线队列），并清掉记住的账号密码，回到登录页。

- **只在设备侧计数与执行**：服务端与对方设备完全不受影响。不做成「服务端按失败次数
  触发」的原因是：用户名是半公开的（可搜索、在好友列表里），任何人都能连发几次错误
  密码，那等于给攻击者一个免费的远程销毁按钮；而「双方清除」还会连带抹掉好友的记录。
- 计数文件在账号目录下、保险库之外（`guard.txt`），重启应用不会清零；登录成功即清零，
  避免零散的历史失败把下一次误输推过阈值。
- **只统计「账号或密码错误」**（服务端 40001）：网络错误、限流、二次验证码错误都不算；
  记住密码导致的自动登录失败也不计数，否则一次改密就会吃掉历史。
- 自毁后重新登录会生成新的设备标识与密钥，本机历史不会恢复（服务端密文还在，但本机
  没有私钥）；旧设备可在设备管理里注销。界面会在登录后说明「本机历史已于某时清空」。
- 注册前会单独弹框确认这条规则，且已写入《用户协议》（2026-12）第三条第 4~5 款。
- 已知边界：能读写你用户目录的恶意程序可以篡改计数。这个功能防的是「别人拿到设备
  在界面上试密码」，不是本地取证。

### 找回邮箱

安全设置页第二张卡片是「找回邮箱」：显示当前绑定的地址（或「未绑定」），
点「绑定邮箱 / 更换或解绑」弹出对话框，需要**当前密码**才能提交。

- 邮箱用于接收找回密码的验证码；服务端按账号加密存储，只在 `GET /user/info`
  里回给账号本人，不会出现在搜索或联系人接口里；
- 留空保存表示解绑，界面会明确提示「之后无法用邮箱找回密码」；
- 客户端按与服务端相同的规则先校验格式，服务端仍会再校验一次。

### 头像

点头像（列表栏左上角）可以「更换头像 / 移除头像」。头像**不是端到端加密**的：
它要给联系人看，服务端必须能直接返回字节。

- 客户端选图后会**重编码成 PNG** 再上传，顺带丢掉 EXIF（相机型号、GPS 坐标不进服务器）；
- 服务端只接受 PNG 且 ≤512KB；读取仅限本人与联系人，其他人拿到用户名也读不到；
- 通讯录与聊天页头部的头像按需拉取（一次最多 30 个联系人），拉不到就回落到首字母头像；
- 移除头像后立刻回到首字母，不影响消息与设备。

### 多设备历史同步

同账号的第二台设备登录后，如果本机没有历史，会自动请求旧设备转发最近记录；
旧设备收到 WS 100022 后弹确认框，显示请求设备 id 与**身份指纹**，同意才转发。

- 只转发「最近 30 天、最多 50 条**文本**」；媒体只留在原设备（消息里会显示为已过期/缺失）。
  只能转发本机有明文的消息——棘轮解不开自己发出的密文，所以「我说过的话」依赖本机留存。
- 归属由源设备身份私钥签名，接收端用已固定的公钥验签；验不过直接丢弃，
  绝不采信服务端给的归属。
- 批准名单存在 `trusted_devices.bin`，只在本机，不上报服务端；同一台设备之后请求不再弹框。
- 设备页每条设备显示「已批准历史同步」，旁边的「撤销授权」只影响能否拉取历史，
  与注销设备、消息收发无关。
- 已知边界：源设备必须在线且有人点确认；旧设备已经不在时，历史补不回来。

### 设备与安全码

联系人页「设备」进入设备管理：可查看本账号设备并注销其它设备
（注销后该设备令牌立即失效）。聊天页「安全码」按对端每台设备展示
60 位安全码，双方排序后哈希，因此两端算出同一个码，可线下核对。

注销是软删除，服务端会拒绝该设备的任何请求。本地已注销设备的登录会给出
明确提示（删除 `~/.mim/<用户名>` 后重新登录，或换设备）；旧设备目录保留，
离线仍可查看历史。若只是服务端缺少设备行（库被清理），登录时会用**同一份**
密钥重新登记，已有会话与棘轮不受影响。

### 账号入口

登录页同时承载三种形态：登录、注册、找回密码。

- **注册**：用户名 / 密码 / 可选邮箱；必须勾选并查看《用户协议》
  （版本 `2026-12`，原文在 `resources/terms/2026-12.txt`，运行时读取）。
  点「注册」后先弹出独立的确认框说明**本机自毁**条款，确认后才提交；
  注册只创建账号：成功后回到登录页并预填用户名，由用户自己登录；
  首次登录才会登记设备、生成密钥。
- **邮箱格式**：客户端按与服务端相同的规则（`^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$`，
  最长 254）先校验，服务端仍会再校验一次。
- **记住账号密码**：仅在登录页提供（注册页不勾选）。勾选后把账号、密码、
  设备名写入 `~/.mim/remember.bin`，用同目录 `remember.key`（0600）做
  AES-GCM 加密；下次启动自动登录。
  退出登录时保留凭据用于表单预填，但把 `autoLogin` 置为 false，
  不会再自动登回去；重新勾选登录后恢复自动登录。
  这只防「随手翻到明文」，不防能读你用户目录的恶意程序，界面已写明。
- **找回密码**：`POST /recover/email` 发验证码、`POST /recover/reset` 重置。
  需要账号绑定邮箱且服务端配置 SMTP；未配置时服务端返回
  「邮件服务未配置」，界面原样提示，不假装成功。

### 联系人操作

聊天页右上「更多」提供：设置备注（`POST /chat/contacts/{peer}/label`）、
屏蔽此人 / 解除屏蔽、清除会话、移除联系人（`DELETE /chat/contacts/{peer}`，双向）。

- **屏蔽是本地行为**：消息仍会解密以推进棘轮，但明文直接丢弃、不提示；
  联系人标记「已屏蔽」，未读数固定为 0，输入区替换为说明条。对方不会收到通知。
- **移除好友是双向的**：服务端同时解除双方关系，本机历史仍保留在保险库里。
- **备注**只影响自己看到的显示名，清空备注即恢复对方昵称。

### 图片、语音与文件

发送：图片经系统文件选择器读取（≤8MB），语音用 16kHz 单声道录音并封装为 WAV，
文件走同一个选择器、只限制大小（≤8MB）。三者都用**一次性随机密钥**做
AES-256-GCM 加密，先把密文上传到 `/media`，再把「媒体 id + 密钥 + 类型 +
尺寸/时长/文件名」放进双棘轮密文一起发出。
服务端只见到密文文件与大小，拿不到密钥、文件名或媒体类型。

接收：下载密文后按消息里的密钥解密；密文缓存在保险库 `media/` 下，
展示时临时解密（内存 LRU 上限 32MB）。清除会话会一并删除本地媒体密文。

文件消息在气泡里是一张卡片（文件名 + 大小），点一下才解密并弹出「另存为」；
默认文件名取末段，防止对端在文件名里塞路径分隔符。保存状态分「解密中 /
已保存 / 保存失败」，失败可以再点一次。

限制：单文件上限 8MB；语音是原始 WAV（未压缩、无波形）；图片只在桌面端解码展示；
文件不做分片上传，超大文件会被明确拒绝。
服务端密文有保留期（默认 30 天，见 `docs/operations.md`）：清除会话或撤回时，
发送方会主动删掉自己上传的密文；即便发送方再也不上线，巡检也会按时间清理。
过期后消息里的附件会显示「已过期或被清理」，需要长期留存请及时另存到本机。

### 置顶与未读定位

- **置顶**：聊天页「更多」→ 置顶会话，或长按联系人列表里的会话来切换；
  只改本机列表顺序（`pinned.bin`），不通知服务端，也不影响对方。
- **未读定位**：打开有未读的会话时，自动滚到本地已读水位之后的第一条对方消息，
  并在上方画「以下为新消息」的分界。已读水位在保险库里。

### 安全码变更提醒

每次打开会话都会计算对端各设备的安全码，并与本机记录比对：

- 首次见到的设备按 TOFU 记为基准，不打扰用户；
- 已记录过的设备**值发生变化**时，聊天页顶部出现红色警示，说明可能是换设备
  或密钥被替换，必须线下重新核对；点「我已核对」后才把新值记为基准。

### 消息搜索

联系人页顶部放大镜进入搜索：在**本机已缓存的加密消息**里按关键词查找，
支持文字、图片说明与语音说明；命中后进入会话并自动滚到那条消息。

服务端没有明文，所以搜索只能在有缓存的消息里做：换设备或清空保险库后，
旧消息搜不到。这一点在搜索页也写明了。

### 输入

- **Enter 发送**，**Shift+Enter 换行**（Ctrl/Alt/⌘+Enter 同样换行）。
- 中文输入法拼写过程中回车是选词，不会误发（检查 `TextFieldValue.composition`）。

### 未读数与清除会话

联系人列表的未读角标取自 `GET /message/unread/{peer}`，避免只靠本地计数漂移；
每个联系人一次请求，因此节流到 5 秒一次，进入联系人页时强制刷新。

聊天页「清除」提供两种语义：

- **只清我的**：服务端记录清除点，仅影响自己；对方记录不受影响。
- **双方清除**：服务端抹掉这段密文，对方也看不到。

两种都会同时丢弃本地缓存（`messages.bin` 中该联系人的记录），
否则下次打开会看到服务端已过滤、本地还留着的旧消息。清除后仍可继续收发。

「双方清除」对**不在线**的对方同样有效：对方在线时靠 100019 推送清本地，
离线时登录 / 刷新列表 / 打开会话会拉一次 `GET /message/clear?peers=...`，
按返回的清除点丢掉本机更早的缓存。缓存条目记录了服务端消息 id，
旧版本写入的、没有 id 的条目按清除时间兜底；这一步只删缓存，不动棘轮状态，
清除后照常收发。

### 本地保险库

默认在 `~/.mim/<用户名>/<设备>/`（可用 `-Dmim.vault.dir` 覆盖）：

- `key.bin` —— 32 字节保险库密钥（0600）
- `bundle.bin` —— 身份密钥 / 预密钥（加密）
- `sessions.bin` —— 会话存储（加密）
- `messages.bin` —— 消息缓存（加密）
- `outbox.bin` —— 离线发送队列（加密，密文已组装，重试只重发）
- `blocked.bin` —— 本机屏蔽名单（不上报服务端）
- `pinned.bin` —— 置顶的会话（本机偏好）
- `read_marks.bin` —— 每个会话的已读水位（毫秒），只用于未读定位
- `safety.bin` —— 见过的对端设备安全码，只用于变更提醒
- `server_ids.bin` —— 本地消息 id 与服务端 id 的映射
- 同级的 `device.txt` 保存稳定设备标识

桌面端只能做到文件权限保护；Android/iOS 应改用 Keystore / Keychain。
清空该目录等于丢弃本设备的私钥与会话，旧消息将无法解密。

### 设备与密钥（KeyRegistry）

`KeyRegistry.provision` 走完整契约：登记设备 → 上传身份公钥 → 上传签名预密钥
→ 批量上传一次性预密钥。密钥材料由 Rust 核心生成（JNI），私钥不出进程。

运行联调测试前需要先构建带 JNI 的动态库：

```bash
cd ../MIMCoreRust && cargo build --release --features jni
cd ../MIMCompose
MIM_SERVER_URL=http://127.0.0.1:8080 \
MIM_NATIVE_LIB=../MIMCoreRust/target/release/libmim_core_rust.dylib \
  ./gradlew :composeApp:desktopTest
```

注意：`cargo build --release` 不带 `--features jni` 会覆盖动态库并去掉 JNI 符号。

服务端校验的是**明文口令**（BCrypt）；上传 Base64 会一直失败。

### 首条消息联调

`FirstMessageTest` 打通「A 组装 → 服务端 → B 拆解」：

- A 用 Rust 生成 X3DH 首条消息（证书信封 + 会话标签 + 双棘轮密文）
- 服务端按 sealed + tag 契约落库
- B 拉 `/message/undelivered`，用 Rust 重建会话并解出明文与证书

同一用例还会把双方会话写入 Rust 的会话存储，再走一轮 sealed 回信
（JNI 往返），验证棘轮推进与标签收敛。

同样需要 `MIM_SERVER_URL` 与 `MIM_NATIVE_LIB`。测试使用固定账号
（首次创建，后续复用），避免撞注册限流。连续反复跑会撞登录限流
（每 IP 每分钟 10 次），等一分钟即可。

## 接 Android / iOS

1. **Android**：在 `composeApp/build.gradle.kts` 的 `kotlin { }` 里加
   `androidTarget()`，把 `desktopMain` 的 UI/状态代码移到 `commonMain`
   （这些文件本来就没有桌面 API），再补 `androidMain` 的入口 `Activity`。
   Rust 核心用 `MIMCoreRust` 的 JNI 绑定（`MimCoreNative`），把 `.so` 放进
   `jniLibs`。
2. **iOS**：Rust 核心编译为静态库 / xcframework，经 `cinterop` 暴露
   `include/mim_core.h` 的函数；UI 复用 `commonMain`。

## 约束

- UI 不接触明文密钥；状态由 Rust 核心的 `secure_store` 加密落盘，
  密钥来自 Android Keystore / iOS Keychain。
- 演示后端只用于验证界面与状态流，不代表协议行为。
